# STM32 Smart Lighting System

Embedded systems project developed at **ENSIM – Le Mans University** as part of the 2025–2026 academic year.

The project explores the design and validation of an **automatic lighting control system** built around an **STM32 NUCLEO-L496ZG** microcontroller.

The system is designed to activate lighting only when:

- human presence is detected by a PIR sensor;
- ambient light is below a configurable threshold measured through an LDR.

The project focuses on embedded peripheral configuration, sensor acquisition, actuator control and incremental hardware/software validation.

---

## Functional principle

The expected lighting logic is:

```text
LIGHT_ON = PRESENCE AND (LIGHT_LEVEL < THRESHOLD)
```

This prevents unnecessary lighting when no person is detected or when ambient light is already sufficient.

## Hardware architecture

The prototype is based on an **STM32 NUCLEO-L496ZG**, integrating an STM32L496ZG ARM Cortex-M4 microcontroller.

### Main components

- STM32 NUCLEO-L496ZG
- STM32L496ZG – ARM Cortex-M4
- PIR presence sensor
- LDR photoresistor
- FS5103B servo motor
- green status LED
- red status LED
- breadboard and passive components

### STM32 peripherals

| Function | Peripheral |
|---|---|
| Presence detection | GPIO |
| Ambient-light acquisition | ADC |
| Servo position control | Timer / PWM |
| Serial monitoring | UART |

| Element | STM32 pin / peripheral | Configuration |
|---|---|---|
| PIR sensor | PF14 | Digital input with pull-down |

| FS5103B servo | TIM3_CH2 | PWM output |
| Serial terminal | LPUART1 | UART transmission |

## Incremental validation strategy

Rather than immediately combining all functions into a single application, the project followed an **incremental validation approach**.

Each critical subsystem was tested independently before attempting full integration.

### 1. PIR presence detection

The PIR sensor is read through GPIO.

Validation included:

- stable digital acquisition;
- pull-down configuration;
- LED status indication;
- rising/falling-edge event detection;
- UART diagnostic messages.

Example behaviour:

```text
Presence detected
Absence detected
```

---

### 2. LDR luminosity measurement

The LDR is connected through a voltage divider and sampled using the STM32 ADC.

Validation included:

- ADC1 configuration;
- 12-bit acquisition;
- interpretation of values between 0 and 4095;
- experimentally selected decision threshold;
- LED indication of low-light conditions.

The light level is evaluated using a condition such as:

```c
if (adc_value < LIGHT_THRESHOLD)
{
    // Low-light condition
}
```

---

### 3. Servo motor control

The FS5103B servo motor is controlled using a hardware PWM generated by **Timer 3**.

Target PWM parameters:

```text
Frequency: approximately 50 Hz
Period:    approximately 20 ms
Pulse:     approximately 1–2 ms
```

Servo position is controlled through the timer comparison register.

The validation program tests successive angular positions to verify:

- PWM stability;
- reproducibility;
- mechanical response;
- position control.

## Experimental results

The validation campaign confirmed the correct operation of the three main subsystems.

### PIR

- stable presence detection;
- correct GPIO behaviour;
- event detection on state changes;
- coherent UART diagnostic messages.

### LDR / ADC

- successful analog acquisition;
- clear distinction between bright and dark environments;
- threshold-based decision logic;
- visual feedback through LED signalling.

### PWM / servo

- stable hardware PWM generation;
- repeatable servo positioning;
- correct response to CCR changes.

---

## Integration findings

The individual subsystems were successfully validated.

During the attempt to combine all functions into a single firmware application, several embedded-software integration issues were identified:

- blocking `HAL_Delay()` calls;
- peripheral configuration conflicts;
- synchronisation issues between ADC acquisition and PIR event processing;
- interactions between timing-sensitive modules.

This led to the decision to maintain three independent validation applications in the repository.

The project therefore demonstrates **validated embedded building blocks and an analysed system-level integration path**, rather than presenting an unfinished integration as a fully production-ready system.

---

## Possible improvements

A future version could improve robustness and integration through:

- non-blocking state-machine architecture;
- interrupt-based event handling;
- SysTick-based scheduling;
- ADC moving-average filtering;
- threshold hysteresis;
- PIR debounce / presence-validation timing;
- minimum lighting hold time after detection;
- full subsystem integration into a single firmware architecture.
